# 게임 만들기 룰북

새 게임을 만들 때 지키는 규칙입니다. 사람이 만들든 AI(Claude)에게 맡기든 똑같이 적용합니다.

---

## 1. 시작 전에 항상 물어볼 것

게임 만들기를 시작하기 전에 **반드시 물어보고, 답을 받은 뒤에** 만듭니다. 짐작해서 정하지 않습니다.

| # | 질문 | 고를 수 있는 것 |
|---|---|---|
| 1 | **캐릭터 타입은 무엇으로 할까요?** | `거울뷰` / `그림자뷰` (아래 2장) |
| 2 | **무엇으로 등수를 매길까요?** | 점수 기준 (예: 맞힌 개수, 먼저 한 순서). 반드시 있어야 함 (아래 8장) |

> 질문이 늘어나면 이 표에 한 줄씩 추가합니다.

### 브랜치: 게임마다 새 브랜치에서 만들고, 다 만든 뒤 main 으로 머지

- 게임을 만들기 시작할 때 **main 에서 새 브랜치를 만듭니다.** 브랜치 이름은 게임 폴더 이름과 같게 합니다(예: `bead`).
  ```
  git checkout main && git pull && git checkout -b <게임이름>
  ```
- main 에서 바로 작업하고 있으면 먼저 새 브랜치로 옮기자고 안내합니다.
- 게임이 다 만들어지고 시험(`?sim=`, 실제 카메라)까지 끝나면 **main 으로 머지**합니다.
  ```
  git checkout main && git merge <게임이름>
  ```
- 머지는 만든 사람이 "다 됐다"고 확인한 뒤에 합니다. AI(Claude)는 머지할지 먼저 묻습니다.

### 에이전트(`agent/`)는 건드리지 않습니다

- 게임을 만들 때 **`agent/` 폴더의 파일은 고치지 않습니다.** 게임은 `games/` 폴더 안에서만 만듭니다(5장).
- 에이전트에 기능이 꼭 필요해 보이면 직접 고치지 말고 먼저 물어봅니다.

## 2. 캐릭터 타입

카메라 앞 사람을 화면에 어떻게 보여 줄지 정한 프리셋입니다.
`games/_shared/video-layer.js`의 `CHARACTER_TYPES`에 미리 만들어 두었으므로, 게임은 이름만 고르면 됩니다.

### 2-1. 거울뷰 (`'mirror'`)
- 카메라 **영상이 그대로** 보입니다.
- 사람의 **테두리에 글로우만** 넣습니다.
- 들어온 사람마다 **테두리 색이 다릅니다**.
  - 플레이어(`players.js`)는 플레이어 색(P1 빨강, P2 파랑, P3 초록, P4 노랑)입니다.
  - 그 밖의 사람은 지금 쓰지 않는 색을 받습니다.

### 2-2. 그림자뷰 (`'shadow'`)
- 카메라 **영상을 하나도 쓰지 않습니다**. 사람 모양(마스크)만 씁니다.
- 사람 테두리에 **옅은 글로우 20%**를 넣습니다. 사람을 구분할 정도로만 넣습니다. 색은 거울뷰처럼 사람마다 다릅니다.
- 사람 모양에 **깃털(feather)을 많이** 주고 **60% 검정**으로 칠해서 **그림자처럼** 보이게 합니다.
- **배경은 게임에서 불러와 붙입니다** (`background` 옵션, 아래 6장 참고).

### 2-3. 스켈레톤 (캐릭터 타입과 별개)
- 뼈대 선은 캐릭터 타입과 **상관없이**, 게임에서 원할 때 **언제든** 붙일 수 있습니다.
- 모두에게 붙이려면 `draw({ skeleton: true })`, 한 사람에게만 붙이려면 `stage.skeleton(body, color)`를 씁니다.

### 수치 조정
진하기와 번짐 정도는 `CHARACTER_TYPES`에서 고칩니다. 바꾸면 모든 게임에 같이 적용됩니다.

| 프리셋 | 값 | 뜻 |
|---|---|---|
| mirror | `glow: 1` | 테두리 글로우 진하기 |
| shadow | `glow: 0.2` | 옅은 글로우 20% |
| shadow | `shadow: 0.6` | 그림자 60% 검정 |
| shadow | `feather: 18` | 테두리 번짐 (마스크 640px 기준) |

## 3. 공통 틀 (모든 게임이 같은 모양)

모든 화면은 `games/_shared/game-shell.js`(`GameShell`)로 **같은 틀**을 씁니다. 화면마다 따로 만들지 않습니다.
**스켈레톤 버튼은 어느 화면에서든 항상 푸터에** 있습니다.

### 게임 고르기 화면 (`games/index.html`)
```
            어떤 운동을 할까요?
   ✋ 손을 들어 하고 싶은 카드 위에 잠시 올려 두세요
      최대 참여 인원 [1명][2명][3명][4명]
      [게임 카드] [게임 카드] …
└ 푸터:            [🦴 스켈레톤]          [⏻ 게임 종료] ┘
```
- **최대 참여 인원**은 이 화면의 안내 문구 밑에서 **한 곳에서만** 정합니다. 게임 안에서는 정하지 않습니다.
- **게임 종료**는 프로그램을 끕니다. 손으로 실수로 누를 수 있어서 "게임을 끝낼까요?"를 한 번 더 묻습니다.
  - "예"를 누르면 에이전트가 게임 창(전용 브라우저 프로필)을 닫고 자기도 꺼집니다(`POST /api/quit`).

### 게임 화면 (`games/<게임>/`)
```
┌ 헤더: 게임 이름 ──────────────────────────────┐
│ 본문: 게임마다 다름 (시작 전 화면 = 제목 · 소제목)     │
└ 푸터: [🔄 게임 다시 시작]   [🦴 스켈레톤]   [🚪 게임 나가기] ┘
```

| 자리 | 내용 |
|---|---|
| 헤더 | 게임 이름 (아이콘 + 이름) |
| 본문 | 게임마다 다름. 시작 전 화면에는 **제목, 소제목** |
| 푸터 왼쪽 | **게임 다시 시작**: 이 게임의 첫 화면(시작 전 화면)으로. 게임 중이면 멈춤 |
| 푸터 가운데 | **스켈레톤**: 보이기/숨기기 |
| 푸터 오른쪽 | **게임 나가기**: 게임 고르기 화면으로 |

### 공통 설정 (모든 게임이 같이 씀, 이 PC에 저장)
| 설정 | 기본 | 뜻 |
|---|---|---|
| `settings.players` | **4** | **최대 인원**(1~4). 사람이 이보다 적어도 **1명 이상이면 게임을 진행**합니다. |
| `settings.skeleton` | 숨기기 | 뼈대 선 표시 |

- 인원은 게임 고르기 화면에서, 스켈레톤은 어느 화면의 푸터에서든 바꿉니다. 바꾸면 모든 게임에 그대로 적용됩니다.
- 최대 인원보다 많이 있으면 카메라에 가까운 사람부터 참여하고, 번호는 화면 왼쪽부터 P1, P2 … 순서입니다. 남은 사람은 게임에 반영하지 않습니다.
- 게임 중에 사람이 새로 들어왔을 때 참여시킬지는 게임마다 정합니다.
  - 청기백기: 시작할 때 인원으로 고정
  - 사진 깨기: 자리가 남으면 중간에 참여

### 사용법 (게임)
```js
import { GameShell, settings } from '../_shared/game-shell.js';
const shell = new GameShell({ name: '게임 이름', icon: '🎮', sim: SIM, onHome: () => setPhase('setup') });

createPlayers(client, settings.players, true);          // 최대 인원까지 (적으면 있는 만큼)
stage.draw({ players, skeleton: settings.skeleton });   // 스켈레톤은 공통 설정을 따름
```
- 게임 화면은 헤더와 푸터 사이에 배치합니다. CSS 변수 `var(--shell-top)`, `var(--shell-bottom)`을 씁니다.
- 게임 안에 "그만하기", "← 게임 고르기", 인원, 스켈레톤 버튼을 **따로 만들지 않습니다.** 모두 공통 틀에 있습니다.

## 4. 손 커서 (손으로 버튼 누르기)

마우스 없이 **손을 들어 버튼을 누르는** 공용 기능입니다. 파일은 `games/_shared/hand-pointer.js`(`HandPointer`)와 `_shared/ui.css`입니다.
**모든 게임의 버튼은 손 커서로 누를 수 있어야 하고**, 게임마다 따로 만들지 않습니다.

### 생김새
| 부분 | 설명 |
|---|---|
| 손 모양 | ✋ |
| 배경 | 손 뒤의 동그란 바탕 |
| 테두리 | 배경을 두른 흰 원 |
| 테두리 인디케이터 | 테두리를 따라 차오르는 초록 줄 (클릭까지 남은 시간) |

### 동작
| 상태 | 언제 | 모습 |
|---|---|---|
| 기본 | 버튼 밖 | 어두운 배경, 흰 테두리 |
| 올라감 | 커서가 버튼 위에 있음 (손이 움직이는 중) | **배경이 연한 초록색** |
| 고정 | 버튼 위에서 손이 멈춤 (0.25초) | **테두리 인디케이터가 켜지며 차오름** |
| 클릭 | 인디케이터가 다 참 (1.5초) | **클릭 이벤트 발생**, 배경이 한 번 반짝 |

- 고정된 뒤 손이 크게 움직이면 인디케이터는 처음부터 다시 찹니다. 손 떨림 정도(화면의 4%)는 멈춘 것으로 봅니다.
- 클릭한 뒤 1.5초 동안은 같은 버튼이 다시 눌리지 않습니다.
- 손을 가슴 높이 이상으로 들면 커서가 나타나고, 내리면 사라집니다.
- 마우스, 터치, 키보드(←→↑↓, Enter)로도 똑같이 누를 수 있습니다. 보호자나 관리자가 쓰는 용도입니다.

### 사용법
```html
<button class="hand-target">시작하기</button>   <!-- 손으로 누를 것에는 hand-target -->
```
```js
import { HandPointer } from '../_shared/hand-pointer.js';
const pointer = new HandPointer({ client, mirror: true, onSelect: el => sound.tick() });
// 매 프레임: pointer.update(dt)
// 게임 중처럼 버튼을 누르면 안 될 때: pointer.enabled = false
```

### 수치 조정 (`new HandPointer({...})` 옵션)
| 옵션 | 기본 | 뜻 |
|---|---|---|
| `dwell` | 1.5 | 고정된 뒤 클릭까지 걸리는 초 |
| `settle` | 0.25 | 이만큼 멈춰야 고정으로 봄 (초) |
| `steadyRadius` | 0.04 | 멈춘 것으로 보는 흔들림 범위 (화면 짧은 변의 비율) |

색은 `ui.css`의 `.hand-cursor` 부분에서 바꿉니다.

## 5. 폴더와 파일

```
games/
├─ index.html          게임 고르기 화면 → 새 게임을 GAMES 목록에 한 줄 추가
├─ _shared/            공용 (모든 게임이 같이 씀) — 게임 하나만을 위한 코드는 넣지 않음
└─ <게임이름>/          게임마다 폴더 하나
    ├─ index.html       화면
    ├─ game.js          진행·판정·점수
    ├─ README.md        규칙·화면·판정 기준 설명
    └─ server/          (서버 기능이 꼭 필요할 때만) C# 게임 모듈
        ├─ *.cs          IGameModule 구현 → 빌드 때 자동 포함, 에이전트 시작 때 자동 연결
        └─ *.props       그 게임만 쓰는 NuGet 패키지
```

- **에이전트(`agent/`)는 게임을 만들 때 고치지 않습니다(1장).** 게임 전용 코드도 넣지 않습니다.
  - 게임 서버 기능은 `games/<게임>/server/`에 둡니다. API 주소는 `/api/<게임>/...`입니다.
  - 휴대폰 같은 다른 기기에 열어 줄 주소는 모듈의 `RemoteAccess`에 적습니다.
  - 예시는 `games/smash/server/`(사진 깨기)를 보세요.
- 웹 파일만 고치면 다시 빌드할 필요가 없습니다. 에이전트가 브라우저를 자동으로 새로고침합니다.

## 6. 코드 사용법

```js
import { FemtoClient, J } from '../_shared/femto-client.js';
import { Stage } from '../_shared/video-layer.js';

const client = new FemtoClient({ sim: SIM });   // 그림자뷰도 마스크가 필요하므로 video 는 기본값(true)
const stage = new Stage(document.getElementById('stage'), client, { character: 'shadow' });   // 또는 'mirror'

const bg = new Image(); bg.src = 'bg.jpg';       // 그림자뷰: 게임이 붙이는 배경

function frame() {
  stage.draw({
    players,            // players.js 플레이어 목록 (사람별 색)
    mirror: true,       // 거울처럼 좌우 반전
    skeleton: false,    // 뼈대 선 (언제든 켤 수 있음)
    background: bg,     // null(투명, 캔버스 뒤 HTML 배경) / 이미지 / '#색' / (ctx, W, H) => {}
  });
  requestAnimationFrame(frame);
}
```

- 사람 영상이 아예 필요 없는 게임(예: 사진 깨기)은 `new FemtoClient({ video: false })`로 만들고 `Stage`를 쓰지 않습니다.
- 카메라 없이 시험할 때는 주소 뒤에 `?sim=인원`을 붙입니다. 이때는 영상이 없습니다.
  - 거울뷰는 뼈대로 보여 줍니다.
  - 그림자뷰는 뼈대로 만든 그림자로 대신 보여 줍니다.

## 7. 공통 원칙 (어르신용)

- 큰 글씨, 큰 버튼, 넉넉한 판정과 시간을 둡니다. 틀려도 말투는 부드럽게 합니다.
- 버튼은 모두 손 커서로 누를 수 있게 합니다(4장). 마우스가 없어도 되게 합니다.
- 음성 안내는 `_shared/sound.js`를 씁니다.
- 인원은 공통 설정의 **최대 인원(기본 4명)**을 따릅니다(3장). 사람이 적어도 1명 이상이면 진행합니다.
- 카메라 없이 `?sim=` 으로 시험할 수 있게 만듭니다.
- 모든 게임에는 **등수를 매길 수 있는 경쟁 요소**가 꼭 들어갑니다(8장).

## 8. 경쟁 요소 (등수)

모든 게임에는 **항상 등수를 매길 수 있는 경쟁 요소**가 들어가야 합니다. 함께 하는 사람끼리 겨루는 재미가 운동을 계속하게 만듭니다.

- **점수 기준을 하나 정합니다.** 숫자로 비교할 수 있어야 합니다. 예: 맞힌 개수, 꿴 구슬 수, 깬 사진 수, 먼저 한 순서 보너스.
- **게임이 끝나면 결과 화면에 등수를 보여 줍니다.** 1·2·3등은 🥇🥈🥉, 그 아래는 `4등`처럼 씁니다.
- **점수가 같으면 공동 등수**로 합니다. 다음 기준(예: 정확도, 먼저 한 횟수)이 있으면 그걸로 가르고, 그래도 같으면 공동입니다.
- **1등을 음성으로 축하합니다.** 예: "○○님이 1등이에요!", 같으면 "공동 일등이에요!"
- 게임 중에도 각 사람의 점수가 **실시간으로 보이게** 합니다(누가 앞서는지 알 수 있게).
- **혼자 할 때도 점수는 똑같이 매기고 보여 줍니다.** 다른 사람이 들어오면 그대로 등수 경쟁이 됩니다.
- 꼴찌를 깎아내리는 표현은 쓰지 않습니다. 모두에게 점수와 칭찬 한마디를 줍니다(7장, 어르신용 말투).

> 지금 게임들의 등수 기준: 청기백기 = 점수(먼저 한 순서 보너스 포함), 사진 깨기 = 맞힌 수(같으면 던진 수 → 마지막 명중 시각), 구슬 꿰기 = 꿴 구슬 수, 벽 구멍 통과 = 통과한 벽 수(끝까지 버틴 사람이 1등). 새 게임을 만들면 여기에 한 줄 추가합니다.
